如何估算热量？

优先用搜索列表里的常见食物参考值（含蛋白质/脂肪/碳水/纤维/钠）；有包装的看营养成分表，填进「营养细节」更准；只填热量不填营养时，按常见供能比例（蛋白 15% · 脂肪 30% · 碳水 55%）自动估算。搜不到的食物添加后会自动记住，下次直接搜。左边数字是「每份」热量，右边可填份数（如 ×2）。

🍽️ 接下来吃什么

按当日预算缺口、营养评分（Nutri-Score 式剖面）与你的偏好排序；过敏原与疾病禁忌已由代码硬过滤，任何推荐都不会越线。只给 2+1 个真正值得吃的，不刷屏。

📋 减脂评估

🔬 校准 · 真实消耗反推

自报摄入平均偏差 20–40%，公式的活动系数也只是一档估计。这里用「体重实测变化 × 7700 千卡/kg」反推你真实的每日消耗，让公式给现实让路。

⚖️ 账实核对

📅 周度评估

周维度看趋势，不纠结单日：「蛋白 5/7 天达标」比「今天差 12g」更能反映真实饮食习惯。趋势变化用回归斜率滤除水分波动；账实差持续为正说明摄入可能被低估。

BMR 按 Mifflin-St Jeor 公式估算；TDEE = BMR + 日常活动消耗（按活动水平折算）。当日总消耗 = TDEE + 运动记录 + 零星消耗记录；每日摄入预算 = TDEE − 目标缺口。缺口建议 200–500 千卡/天（约每周减 0.2–0.5 kg），不建议长期超过 800。

过敏原（勾选后含该成分的食物从推荐中完全排除）

💾 数据管理

数据保存在本机浏览器，并自动镜像到浏览器数据库（IndexedDB）防丢失，不会上传。「加密导出」用 AES-GCM 端到端加密，密码不设恢复，忘了就解不开。建议每两周导出一次。

☁️ 跨设备同步 GitHub 私有 Gist · 端到端加密

数据用上方「备份密码」AES-GCM 加密后存进你自己的私有 Gist，GitHub 只见密文；上传前会先与云端合并，不会互相覆盖。另一台设备填同一 Token、Gist ID 和密码，点「从云端合并」即可。Token 只存本机浏览器，不进入备份文件。获取 Token：github.com/settings/tokens → Generate new token (classic) → 勾选 gist。
